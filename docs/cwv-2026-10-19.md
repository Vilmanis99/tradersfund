## Biggest LCP issue found and fixed
**Root `app/loading.tsx` Suspense fallback.** Every prerendered page shipped a skeleton first and the real page body in a hidden `<div id="S:0">` at the end of the HTML, swapped in by an inline `$RC` script once the whole document (up to 610 KB on `/prop-firm-challenges`) had been parsed. The LCP element (`.blog-hero-sub` on the main table) was therefore painted late: LCP breakdown before = TTFB ~0.45 s + **render delay 1.9–2.9 s**, with FCP at 1.2 s showing only the header and skeleton.

Fix: removed `app/loading.tsx`. The body now streams in document order. The same boundary was also why `notFound()` on unknown `/blog/<slug>`, `/compare/<matchup>` and `/authors/<slug>` returned HTTP 200 (the status was already committed when the not-found UI streamed in); those now return 404. `scripts/check-light-release.mjs` asserted the skeleton file existed; it now asserts the file is absent, with the reason.
